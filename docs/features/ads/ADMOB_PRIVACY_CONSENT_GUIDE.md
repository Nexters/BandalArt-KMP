# AdMob 개인정보 동의 개념 가이드

## 문서 목적

UMP 연동([전략 문서](ADMOB_UMP_CONSENT_STRATEGY.md))을 이해하는 데 필요한 광고 개인정보 동의 개념을 정리한다. 용어가 왜 필요한지, BandalArt의 광고 수익과 어떻게 연결되는지에 집중한다.

법률 자문이 아니다. 규정 세부 내용과 날짜는 Google 공식 문서를 기준으로 다시 확인한다.

## 한 장 요약

```text
사용자 지역 판별 (UMP)
 ├─ 동의 대상 지역 (EEA·영국·스위스 등)
 │   ├─ 동의 양식 표시 → 사용자가 선택
 │   │   ├─ 맞춤 광고 동의 ─────────→ 맞춤 광고 (단가 높음)
 │   │   ├─ 기기 저장 동의만 ──────→ 비맞춤 광고
 │   │   └─ 기기 저장 거부 ────────→ 제한 광고 (단가 낮음, 노출 적음)
 │   └─ 인증 CMP가 없음 ────────────→ 광고가 거의 나가지 않음 ← BandalArt 기존 상태
 └─ 그 외 지역 (한국·일본 등)
     └─ 양식 없음 → 앱이 요청한 방식대로 광고
```

## 용어

| 용어 | 뜻 | BandalArt와의 관계 |
| --- | --- | --- |
| GDPR | EU 일반 개인정보보호법. 개인정보 처리에 법적 근거(동의 등)를 요구한다. | EEA 사용자에게 적용된다. |
| ePrivacy 지침 | 기기에 정보를 저장하거나 읽을 때 동의를 요구하는 EU 규정. "쿠키 법"으로 불린다. | 광고 SDK가 기기 저장소와 식별자를 쓰므로, 비맞춤 광고에도 동의가 필요할 수 있는 이유다. |
| EEA | EU 27개국 + 아이슬란드·리히텐슈타인·노르웨이 | 영국과 스위스는 EEA가 아니지만 Google이 같은 동의 요구를 적용한다. |
| IAB TCF | 업계 표준 동의 프레임워크(Transparency & Consent Framework). 사용자의 선택을 목적(Purpose)·벤더별로 문자열에 담아 광고 기술 회사에 전달한다. | UMP가 TCF 문자열을 만들고 GMA SDK가 광고 요청에 자동으로 실어 보낸다. 앱 코드가 직접 다룰 일은 없다. |
| CMP | 동의 관리 플랫폼(Consent Management Platform). 동의 양식을 띄우고 TCF 문자열을 저장하는 도구 | Google은 EEA·영국 광고에 **Google 인증 CMP** 사용을 요구한다. |
| UMP | Google이 무료로 제공하는 인증 CMP(User Messaging Platform) SDK | 이번 작업에서 연동한다. 양식 문구는 AdMob 콘솔의 "개인 정보 보호 및 메시지"에서 관리한다. |

## Google 인증 CMP 요구사항

- 2024년 1월부터 EEA·영국, 2024년 7월부터 스위스 사용자에게 광고를 내보내려면 Google 인증 CMP가 필요하다.
- 인증 CMP가 없으면 해당 지역에서는 광고가 거의 나가지 않는다.
- 앱에서 `npa=1`로 비맞춤 광고만 요청해도 이 요구는 충족되지 않는다. 기기 저장 동의(TCF Purpose 1) 같은 동의 신호 자체가 없기 때문이다.
- BandalArt의 AdMob 국가별 보고서에서 오스트리아·체코·프랑스·영국이 요청은 있는데 eCPM이 `—`였던 것이 이 증상이다.

## 광고 종류: 맞춤 · 비맞춤 · 제한

| 종류 | 사용하는 정보 | 단가 | 언제 나가는가 |
| --- | --- | --- | --- |
| 맞춤 광고 | 광고 ID, 과거 앱·웹 이용 기반 관심사 | 가장 높음 | 맞춤 광고 동의, 또는 동의가 필요 없는 지역에서 앱이 막지 않을 때 |
| 비맞춤 광고 | 현재 앱 문맥, 대략적 위치. 빈도 제한과 부정 방지를 위해 식별자를 쓸 수 있다. | 중간 | 맞춤을 거부했거나 앱이 `npa=1` 등으로 강제할 때 |
| 제한 광고 | 기기 저장소와 식별자를 쓰지 않는다. 빈도 제한도 어렵다. | 낮음 | 동의 대상 지역에서 기기 저장 동의가 없을 때 |

동의 대상 지역에서는 UMP가 만든 동의 결과가 광고 종류를 정한다. 앱이 맞춤 광고를 따로 막을 필요가 없다.

## UMP 동작에서 헷갈리기 쉬운 점

| 항목 | 동작 |
| --- | --- |
| `requestConsentInfoUpdate` | 실행할 때마다 호출한다. 이 호출 전에는 `canRequestAds()`가 false다. 다만 호출 직후에는 이전 실행에 저장된 동의 상태로 true가 될 수 있다(아래 "이전 실행의 동의"). |
| `canRequestAds()` | "맞춤 광고에 동의했는가"가 아니다. **광고를 요청해도 되는 상태인가**다. 동의 대상 지역에서 사용자가 거부를 골라도 동의 절차를 마쳤으면 true가 될 수 있다. 이때 광고 종류는 TCF 문자열이 정한다. |
| 이전 실행의 동의 | 갱신 응답 전이라도 `canRequestAds()`가 true일 수 있다. 바로 광고를 준비해 첫 화면 지연을 줄인다. |
| 확인 실패 | 오프라인 등으로 갱신이 실패하고 저장된 동의도 없으면 `canRequestAds()`가 false다. BandalArt는 이번에는 광고를 쉬고, 다음 화면 생성(Android)이나 다음 active(iOS)에서 다시 확인한다. |
| 개인정보 옵션 | `privacyOptionsRequirementStatus`가 REQUIRED인 사용자에게는 동의를 바꿀 수 있는 진입점을 제공해야 한다. BandalArt는 설정 → 개인정보 옵션이다. |
| 동의 대상 지역 판별 | UMP가 IP 기반으로 판별한다. 개발 중에는 debug geography로 EEA를 흉내 낸다. |
| App ID | UMP는 manifest의 `com.google.android.gms.ads.APPLICATION_ID`에서 App ID를 읽는다. GMA Next-Gen은 코드로 App ID를 넘기므로 manifest 값을 별도로 넣어야 한다. |

## 플랫폼별 광고 식별자

| 플랫폼 | 식별자 | 사용 조건 |
| --- | --- | --- |
| Android | 광고 ID(AAID) | 사용자가 OS 설정에서 삭제하거나 맞춤 광고를 끌 수 있다. |
| iOS | IDFA | ATT 권한 팝업에서 허용해야 쓸 수 있다. BandalArt는 #519부터 UMP의 IDFA 설명 메시지로 ATT를 요청한다. |

UMP의 "IDFA 설명 메시지"를 AdMob 콘솔에 만들면 UMP가 ATT 팝업 앞에 설명 화면을 띄운다. 앱 코드에는 `NSUserTrackingUsageDescription` 문구만 추가하면 된다.

비맞춤 강제를 제거하면 iOS에서는 맞춤 광고가 Apple 기준의 추적에 해당할 수 있다. Apple은 타사 SDK가 앱 데이터를 다른 앱 데이터와 결합해 광고를 타깃팅하는 경우를 추적의 예로 들고, 추적에는 ATT 허용을 요구한다. BandalArt는 1.8.2 제출 준비 중 개인정보 라벨의 추적 질문에서 이를 확인해 ATT를 함께 도입했다.

## 미국 주 개인정보법

캘리포니아(CCPA/CPRA) 등 일부 미국 주는 사전 동의가 아니라 **거부(opt-out)** 방식이다. AdMob 콘솔의 "미국 주 규정" 메시지를 만들면 UMP가 해당 주 사용자에게 거부 진입점을 제공한다. BandalArt는 이번 범위에서 다루지 않는다. 미국 eCPM이 높으므로(약 US$2.44) 후속 검토 대상이다.
