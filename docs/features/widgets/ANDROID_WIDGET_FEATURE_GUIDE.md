# Android 위젯 기능 가이드

## 문서 목적

이 문서는 현재 Android 홈 화면 위젯이 실제로 지원하는 기능과 제약을 정리한다. 구현 계획과 과거 결정을 다루는 [Android Glance 위젯 MVP 전략](ANDROID_WIDGET_MVP_STRATEGY.md)과 달리, 제품 기획과 후속 기능 우선순위를 검토할 때의 현재 기준으로 사용한다. 표시 대상의 상세 우선순위는 [Android 위젯 표시 대상 선택 가이드](ANDROID_WIDGET_SELECTION_GUIDE.md)를 따른다.

## 현재 지원 기능

### 표시할 반다라트

- 앱에서 마지막으로 본 반다라트를 모든 위젯에 자동으로 반영한다.
- 마지막 조회 기록이 아직 없으면 위젯 설정에서 저장한 반다라트를 fallback으로 표시한다.
- 세부 목표는 해당 반다라트에서 마지막으로 열어본 항목을 표시한다. 기록이 없으면 기존 설정값, 제목이 있는 첫 번째 세부 목표 순으로 대체한다.
- 최근 세부 목표는 반다라트별로 저장하므로 다른 반다라트의 데이터가 섞이지 않으며 A → B → A 전환 시 A의 마지막 세부 목표를 복원한다.
- 현재 자동 추적은 위젯 인스턴스별이 아니라 앱의 단일 마지막 조회 기록을 기준으로 한다. 따라서 여러 위젯을 배치해도 반다라트는 함께 바뀐다.

### 크기별 화면

| 크기 | 표시 내용 | 상호작용 |
| --- | --- | --- |
| Small | 프로필 이모지, 메인 목표, 전체 달성률 | 위젯을 눌러 해당 반다라트 열기 |
| Medium | 프로필 이모지, 메인 목표, 달성률, 세부 목표, 할 일 최대 2개 | 목표 영역으로 앱 열기, 할 일 완료 상태 토글 |
| Large | 프로필 이모지, 메인 목표, 달성률, 세부 목표, 할 일 최대 5개 | 목표 영역으로 앱 열기, 할 일 완료 상태 토글 |

- 위젯 너비와 높이에 따라 Small, Medium, Large 레이아웃을 반응형으로 선택한다.
- 제목이 비어 있는 할 일은 표시하지 않는다.
- 메인 목표 제목이 비어 있으면 현지화된 기본 제목을, 프로필 이모지가 없으면 `🎯`를 표시한다.
- 달성률은 0~100 범위로 보정한다.

### 설정과 복구

- 위젯 추가 또는 재설정 화면에서 반다라트와 선택적 세부 목표를 고를 수 있다.
- 설정에 저장한 반다라트는 마지막 조회 기록이 없을 때의 fallback으로 사용한다.
- 선택 정보가 없으면 설정 안내 상태를 표시하고, 누르면 설정 화면을 연다.
- 대상 반다라트가 삭제되었으면 삭제 안내 상태를 표시하고, 누르면 다시 설정할 수 있다.
- 위젯별 설정값은 Glance의 인스턴스별 저장소에 유지된다.

### 앱 연동과 갱신

- 위젯의 목표 영역을 누르면 앱에서 해당 반다라트를 연다.
- Medium/Large 위젯에서 할 일을 누르면 Room 데이터의 완료 상태와 달성률을 갱신한다.
- 앱에서 반다라트 데이터가 바뀌거나 마지막으로 본 반다라트가 바뀌면 설치된 위젯 전체를 갱신한다.
- 위젯에서 할 일을 바꾸면 저장 완료 후 관련 위젯을 즉시 갱신한다.
- 앱에서 마지막으로 본 세부 목표가 바뀌면 설치된 위젯 전체를 갱신한다.
- 백그라운드 진입과 데이터 변경 갱신은 직렬로 처리해 오래된 snapshot이 최신 표시를 덮어쓰지 않게 한다.
- 정기 polling은 사용하지 않는다. 서버에서만 데이터가 바뀌고 앱 프로세스가 이를 관찰하지 못하는 경우에는 별도 동기화 계기가 필요하다.

### 플랫폼과 표현

- 이 문서는 Android 홈 화면용 Jetpack Glance 위젯만 다룬다. iOS WidgetKit 구현 기준은 별도 문서를 따른다.
- 홈 화면 배치와 가로·세로 크기 변경을 지원한다.
- 라이트·다크 테마용 색상을 제공한다.
- 한국어, 영어, 일본어 문구를 제공한다.

## 현재 제약과 기획 시 고려사항

1. 마지막으로 본 반다라트가 모든 위젯에 공통 적용되어, 여러 위젯에 서로 다른 반다라트를 계속 고정하는 용도와 충돌한다.
2. 제목이 있는 세부 목표가 하나도 없으면 Medium/Large 위젯에 할 일이 나타나지 않는다.
3. 표시 가능한 할 일은 Medium 2개, Large 5개이며 정렬은 snapshot이 제공하는 순서를 따른다.
4. 위젯에서는 완료 토글만 가능하고 목표·할 일 추가, 제목 편집, 삭제는 앱에서 해야 한다.
5. 5x5 반다라트 전체 구조나 세부 목표별 진행률 비교는 표시하지 않는다.
6. launcher별 크기, 글자 확대, 재부팅 복원 같은 최종 체감 품질은 실제 기기 QA가 필요하다.

## 추가 기능 후보

### 우선 검토 추천

| 후보 | 사용자 가치 | 기획 결정이 필요한 부분 |
| --- | --- | --- |
| `최근 항목 따라가기` / `이 위젯에 고정` 모드 | 여러 위젯을 서로 다른 목적으로 사용할 수 있다 | 기본 모드, 기존 위젯 마이그레이션 |
| 마감일·D-day·오늘 할 일 강조 | 홈 화면에서 다음 행동을 빠르게 판단할 수 있다 | 정렬 우선순위, 기한 지난 항목 표현 |
| 할 일 추가 바로가기 | 위젯에서 앱의 입력 화면으로 곧바로 이동한다 | 어느 반다라트·세부 목표에 추가할지 |
| 진행률 시각화 | 숫자보다 전체 진행 상황을 빠르게 파악한다 | 원형/막대/미니 3x3 표현과 크기별 밀도 |

### 후속 확장 후보

- 완료하지 않은 할 일만 보기, 완료 항목 숨기기, 사용자 지정 정렬
- 세부 목표별 진행률 또는 3x3 미니맵
- 오늘 완료한 개수, 연속 달성일, 주간 변화 같은 요약 지표
- 위젯에서 세부 목표 전환 또는 다음/이전 반다라트 탐색
- 새로고침 버튼과 마지막 갱신 시각 표시
- 잠금 화면·Android 15 이상 플랫폼별 위젯 최적화 검토
- iOS WidgetKit과 App Group 기반 공통 경험
- 접근성 설명, 고대비, 큰 글자 레이아웃 강화

## 추천 진행 순서

1. 실제 사용 시나리오를 먼저 `최근 항목 자동 추적`과 `위젯별 고정` 중 어떤 쪽이 핵심인지 결정한다.
2. 마감일 또는 진행률 시각화 중 홈 화면에서 가장 자주 확인할 정보 하나를 추가한다.
3. 실제 launcher QA와 사용 지표를 확인한 뒤 편집·탐색 같은 고비용 상호작용을 확장한다.

## 검증 기준

- 최근 반다라트 변경, 설정 fallback, 반다라트별 최근 세부 목표와 첫 유효 항목 대체 규칙은 순수 상태 변환 테스트로 고정한다.
- 최근 반다라트와 반다라트별 최근 세부 목표의 기본값, 저장, Flow 방출을 DataStore 테스트로 확인한다.
- Small/Medium/Large 상태 변환, 삭제·미설정 상태, 할 일 action 파라미터를 Android 단위 테스트로 확인한다.
- 최종 출하 전에는 실제 launcher에서 추가, 크기 변경, 앱 왕복, 완료 토글, 삭제 후 재설정을 확인한다.
