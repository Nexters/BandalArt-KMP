# 넓은 화면 반다라트 표 레이아웃 전략

- 작성일: 2026-10-12
- 관련 이슈: [#434 넓은 화면에서 반다라트 표 레이아웃 개선](https://github.com/Nexters/BandalArt-KMP/issues/434), [#424 iPhone Duo 대응](https://github.com/Nexters/BandalArt-KMP/issues/424)
- 기한: 2027년 4월 전 (Duo 스크린샷 제출)

## 결정

| 항목 | 결정 |
|---|---|
| 분기 기준 | 기기 종류·방향이 아니라 **홈 콘텐츠 영역의 가용 크기**. `BoxWithConstraints`로 판단한다 |
| 2단 조건 | 가용 너비 ≥ 가용 높이 × 0.9. 처음엔 1.2배로 정했으나 Fold2 펼침 홈 영역(density 3.0, 약 589 × 609dp)이 1단에서는 표가 잘려 낮췄다. 세로 휴대폰은 약 0.55라 영향이 없다 |
| 2단 배치 | 왼쪽 정보 영역(이모지, 제목, 메뉴, 달성률·기간, 진행 바, 공유 버튼), 오른쪽 표. 표 한 변 = min(가용 높이 − 상단 바, 가용 너비 × 0.6) |
| 1단 배치 | 현재 구조 유지. 표 한 변 = min(가용 너비 − 좌우 여백, max(남은 높이, 360dp)). 360dp 하한으로 세로 휴대폰 표 크기는 바뀌지 않는다 |
| 셀 텍스트 | 표 한 변 300~400dp(세로 휴대폰)는 그대로. 400dp 초과는 비례 확대(최대 1.5배), 300dp 미만은 비례 축소(최소 0.85배) |
| 화면 방향 | Android 휴대폰도 가로 허용(`screenOrientation="portrait"` 제거). iOS는 현재처럼 iPhone 가로 허용 유지 |
| 온보딩 | 같은 크기 규칙을 적용해 "시작하기" 버튼이 이미지를 가리지 않게 한다 |

## 배경

- `BandalartChart`는 `maxWidth - 30.dp`를 한 변으로 쓰는 정사각형이라 너비가 커지면 높이도 커진다.
- Duo 안쪽(2853 × 2007), Fold2 펼침(1768 × 2208)에서 표 하단이 잘려 스크롤해야 한다.
- iOS는 `UISupportedInterfaceOrientations`에 가로가 이미 있어 휴대폰 가로에서도 같은 문제가 난다.
- Android는 `MainActivity`가 세로 고정이지만, targetSdk 36 앱은 Android 16의 sw600dp 이상 화면에서 방향 고정이 무시된다. 폴더블·태블릿은 이미 가로가 나온다.

## 대안 검토

| 안 | 내용 | 기각 이유 |
|---|---|---|
| 1단 + 높이 맞춤만 | 표만 남은 높이에 맞춰 축소 | 휴대폰 가로에서 헤더가 높이를 차지해 표가 화면 높이의 60% 수준으로 작아진다 |
| 1단 + 최대 너비 | 표 최대 너비 고정 | Duo·휴대폰 가로에서 여전히 스크롤. 양옆 빈 공간만 늘어난다 |

## 단계

### 1. 표 크기 입력화

- `BandalartChart`에 `maxBoardSize` 파라미터를 추가한다. 한 변 = min(가용 너비 − 30dp, `maxBoardSize`).
- 세로 휴대폰에서 지금과 같은 크기가 나오는지 확인한다.

### 2. 홈 레이아웃 분기

- `Home.kt`의 스크롤 `Column` 안쪽을 가용 크기로 분기한다.
- 2단에서는 `HomeHeader`와 `HomeShareButton`을 왼쪽 열로 옮긴다. `HomeTopBar`와 배너 광고 위치는 유지한다.
- 공유 이미지(`homeGraphicsLayer`)는 정보와 표를 함께 캡처한다. 2단에서는 가로형 이미지가 되고, 공유 버튼은 캡처 영역 밖에 겹쳐 둔다.
- 저장·완료 이미지(`completeGraphicsLayer`)는 표만 캡처하므로 배치와 무관하다.

### 3. 셀 텍스트 크기

- `BandalartChart`가 `LocalCellTextScale`로 배율을 내려주고 `CellText`가 글자 크기·줄 높이·자간에 곱한다.

### 4. 온보딩

- 2페이지의 "시작하기" 버튼을 겹쳐 두지 않고 Column 아래에 둔다. 이미지는 남은 영역(`weight(1f)`) 안에서 `aspectRatioBasedOnOrientation(1f)`로 짧은 변에 맞춘다.

### 5. Android 가로 허용

- `AndroidManifest.xml`에서 `android:screenOrientation="portrait"`를 제거한다.
- 회전 시 Activity 재생성 경로 점검
  - 작성 중 시트 draft, 날짜·시간 피커 선택값 유지 (`rememberRetained`, `rememberSaveable`)
  - 배너 광고가 회전마다 재요청되는지
  - 툴팁(Balloon) 위치

## 휴대폰 가로 (낮은 높이) 배치

2.6.2 내부 테스트에서 일반 휴대폰을 가로로 돌리면 표가 약 180dp로 작고, 정보 열이 표보다 길어 표 아래쪽과 공유 버튼이 광고 밑으로 잘렸다.

| 높이를 차지하는 것 (휴대폰 가로, 약 384dp) | 높이 |
|---|---|
| 상태바 | 약 24dp |
| 상단 바 | 62dp + 구분선 |
| 배너 광고 | 50dp |
| 위아래 여백 | 32dp |
| 표에 남는 높이 | 약 180~200dp |

### 결정

- 조건: 2단 조건을 만족하고 홈 전체(광고 포함) 높이가 420dp 미만
- 상단 바와 배너 광고를 왼쪽 정보 열로 옮기고, 표는 홈 전체 높이를 쓴다. 표 한 변 약 180dp → 약 340dp
- 정보 열은 `HomeHeader(compact = true)`: 이모지와 제목을 한 줄로 두고 위아래 여백을 줄인다
- 공유 이미지(`homeGraphicsLayer`)는 정보 열 + 표를 캡처하고, 상단 바·공유 버튼·광고는 캡처 영역 밖에 겹쳐 둔다
- 폴더블 펼침, Duo 안쪽, 세로 휴대폰은 바뀌지 않는다

### 대안

| 안 | 기각 이유 |
|---|---|
| 정보 열만 압축 | 표 크기가 그대로라 작게 보이는 문제가 남는다 |
| 휴대폰은 세로 고정 | Android는 가능하지만 iOS는 iPhone Duo도 iPhone이라 기기 종류로 나눌 수 없다 |

### 확인

- Android 휴대폰 가로: 표·공유 버튼 잘림 없음, 광고와 공유 버튼 사이 간격
- Android Fold2 펼침, iOS Duo 안쪽: 기존 2단 배치 유지
- iPhone 가로: 노치 쪽 inset 침범 없음
- 공유 이미지에 상단 바·공유 버튼·광고가 들어가지 않음

## 확인 기기

| 화면 | 기대 결과 |
|---|---|
| 세로 휴대폰 | 지금과 동일 |
| 휴대폰 가로 (Android·iOS) | 2단, 스크롤 없이 표 전체 |
| Fold2 펼침 | 2단, 표 전체가 스크롤 없이 보임 |
| Fold 반 접힘·가로 펼침 | 비율에 따라 1단/2단 |
| iPhone Duo 안쪽 | 2단 |
| iPhone Duo 바깥쪽 | 지금과 동일 |

## 완료 조건

- 위 확인 기기에서 표 전체가 스크롤 없이 보인다.
- 온보딩 버튼이 이미지를 가리지 않는다.
- 세로 휴대폰 표시와 공유 이미지가 바뀌지 않는다. 2단 화면의 공유 이미지는 가로형이다.
- Android 회전 후 작성 중 상태가 유지된다.
