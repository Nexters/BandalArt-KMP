# 이번 주 할 일 3개 고르기 전략

- 작성일: 2026-11-26
- 관련 이슈: [#499 주간 회고에서 '이번 주에 할 3개' 고르고 홈에서 실행하기](https://github.com/Nexters/BandalArt-KMP/issues/499)
- 상위 이슈: #366 주간 집중 및 회고 루프 (이 문서는 고르기 → 홈에서 실행하기만 다룬다)
- 참고: [주간 회고 알림과 진행률 요약](../notifications/WEEKLY_REVIEW_REMINDER_STRATEGY.md), [넓은 화면 2단 배치](WIDE_SCREEN_BOARD_LAYOUT_STRATEGY.md), [태스크 셀 빠른 완료](TASK_CELL_HAPTIC_COMPLETION_STRATEGY.md)

## 목표

- 주간 회고를 닫은 뒤 5×5 표를 다시 훑지 않아도 이번 주에 할 일을 바로 고를 수 있다.
- 고른 할 일을 홈 상단 바의 드롭다운에서 보고 체크한다. 표 위치와 크기는 바꾸지 않는다.

## 결정

| 항목 | 결정 |
|---|---|
| 범위 | 홈에 열려 있는 현재 반다라트 하나. 회고 시트는 모든 반다라트를 요약하지만, 고르기는 현재 반다라트의 할 일 칸만 다룬다 |
| 저장 위치 | DataStore 문자열 키 `weekly_focus_tasks_{bandalartId}`. 값은 `{weekStart};{cellId},{cellId}`. 새 테이블과 Room 마이그레이션은 없다 |
| 참조 방식 | 할 일 칸 id만 저장한다. 제목과 완료 상태는 매번 현재 표에서 읽는다 |
| 주 기준 | `weekStartOf(DailyResetDateProvider.today())`. 회고와 같은 기기 현지 월요일 |
| 주 비교 위치 | 저장소. 저장된 `weekStart`가 이번 주와 다르면 빈 목록을 돌려준다. presenter는 시계를 모른다 |
| 상한 | 3개. 중복 id는 저장 전에 제거한다 |
| 백업 | 넣지 않는다. 주간 회고 상태와 같은 기기별 단기 상태다. 복원 시 기존 키는 지운다(아래 참고) |
| 자동 이월·추천·알림·위젯 | 이번 범위에서 제외한다 |

## 데이터

`BandalartDataStore`

- `getWeeklyFocusTasks(bandalartId): StoredWeeklyFocusTasks?` (`weekStart: String`, `cellIds: List<Long>`)
- `setWeeklyFocusTasks(bandalartId, weekStart, cellIds)`. 빈 목록이면 키를 지운다.
- `removeWeeklyFocusTasks(bandalartId)`
- `restoreBackupPreferences`의 `bandalartIdsToClear`에서 이 키도 지운다. 복원 후에는 같은 id가 다른 칸을 가리킬 수 있기 때문이다.

`BandalartRepository`

- `getWeeklyFocusTaskIds(bandalartId): List<Long>`: 이번 주에 저장한 선택만 돌려준다.
- `setWeeklyFocusTaskIds(bandalartId, cellIds)`: 이번 주 `weekStart`와 함께 저장한다. 중복을 빼고 앞에서 3개만 남긴다.
- `deleteBandalart`가 반다라트를 지울 때 키도 지운다.

## 표시할 항목 계산

`LoadedBandalart`에 이번 주 선택 id를 함께 담는다. `readBandalart`가 표를 다시 읽을 때마다 선택도 다시 읽으므로, 표를 바꾸는 모든 경로(셀 수정·삭제, 빠른 완료, 일일 초기화)를 지나면 드롭다운 항목도 맞춰진다.

표시 항목 = 저장된 id 순서대로, 현재 표의 할 일 깊이 칸 중 제목이 비어 있지 않은 칸.

- 할 일 칸을 지우면 행은 남고 제목만 비워지므로(`resetTaskCell`), 제목 필터가 "삭제된 칸은 목록에서 빠진다"를 처리한다.
- 상위 목표를 지우면 하위 할 일 제목도 비워지므로 같은 규칙으로 빠진다.
- 저장된 id는 바로 지우지 않는다. 표시 항목이 비면 칩만 숨긴다.

## 주 경계

- 새 주가 되면 저장소가 빈 목록을 돌려주므로 칩이 사라진다. 원래 할 일과 완료 기록은 건드리지 않는다.
- 앱을 연 채 일요일에서 월요일로 넘어가는 경우: 홈이 주기적으로 보내는 `CheckDueDailyResets`에서 현재 반다라트의 선택을 다시 읽고, 바뀌었으면 상태를 고친다.

## 화면

### 회고 시트

요약 아래에 `이번 주 할 일 고르기` 버튼을 둔다. 홈에 반다라트가 없으면 버튼을 숨긴다. 시트는 한 번에 하나만 열리므로, 누르면 회고 시트 대신 선택 시트를 연다.

### 선택 시트

- 후보: 현재 반다라트에서 제목이 있는 할 일 칸 중 미완료 칸, 그리고 이미 고른 칸(완료됐어도 해제할 수 있게). 상위 목표 순서, 그 안의 칸 순서로 나열하고 상위 목표 제목을 함께 보여준다.
- 3개를 고르면 나머지 칸은 비활성화한다. 제목 옆에 `2/3`처럼 선택 수를 보인다.
- `저장`을 눌러야 반영한다. 저장 없이 닫으면 기존 선택이 그대로다.
- `전체 해제`는 시트 안의 선택만 비운다. 저장해야 반영된다.
- 후보가 없으면 안내 문구만 보여준다.

### 홈 상단 바 드롭다운

처음에는 표 위에 카드를 두었지만, 세로 휴대폰에서는 표가 최소 크기(`MIN_SINGLE_COLUMN_BOARD_SIZE`)를 유지하므로 카드 높이만큼 표와 `공유하기`가 화면 아래로 밀렸다(Galaxy S25+ 실기기 확인). 그래서 높이를 쓰지 않는 상단 바 칩과 겹쳐 펼치는 드롭다운으로 바꿨다.

- 칩: 상단 바의 앱 이름과 설정 버튼 사이에 `이번 주 1/3 ▾`. 선택한 할 일이 하나 이상 남아 있을 때만 보인다. 자리가 좁으면 글자를 줄임표로 자른다.
- 펼침: 칩을 누르면 드롭다운이 표 위에 겹쳐 열린다. 레이아웃 높이는 그대로다.
  - 제목 `이번 주 할 일`, 완료 수 `1/3 완료`, 할 일 행(체크 + 제목), `수정`.
  - Android는 Material `DropdownMenu`, iOS는 hig `CupertinoDropdownMenu`의 `MenuPickerAction`으로 그린다.
- 체크는 기존 `ToggleTaskCompletion`을 그대로 쓴다. 원래 칸의 완료가 바뀌고 표를 다시 읽으므로 드롭다운과 표가 함께 바뀐다. 햅틱, 완료 기록, 위젯 안내도 같은 경로를 탄다. 체크해도 드롭다운은 닫지 않는다.
- `수정`은 드롭다운을 닫고 선택 시트를 연다.
- 완료한 항목도 남긴다(취소선 또는 체크 표시).
- 펼침 여부는 상단 바 안의 일시 UI 상태다. 저장하지 않는다.

### 배치

상단 바는 세로, 넓은 2단, 짧은 가로(휴대폰 가로) 배치에 모두 있으므로 세 배치 모두 같은 칩을 보인다. 상단 바는 공유 이미지 캡처 영역 밖이라 공유 결과도 바뀌지 않는다.

## 검증

- DataStore: 저장·읽기, 빈 목록 저장 시 키 삭제, 복원 시 키 삭제.
- 저장소: 같은 주에는 그대로, 다음 주에는 빈 목록, 중복 제거와 3개 상한, 반다라트 삭제 시 키 삭제.
- presenter: 회고에서 선택 시트 열기, 3개 상한, 저장 후 표시 항목, 저장 없이 닫으면 유지, 체크로 원래 칸 완료, 제목이 빈 칸 제외, 반다라트 전환, 주 경계 후 `CheckDueDailyResets`로 항목 비움.
- 실기기: 세로 휴대폰에서 칩이 생겨도 표와 `공유하기` 위치가 그대로인지, 드롭다운 체크가 표에 반영되는지.
- Android·iOS 컴파일, spotless, detekt.
