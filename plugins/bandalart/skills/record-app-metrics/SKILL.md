# Record App Metrics

BandalArt의 배포·사용 통계를 나중에 다시 비교할 수 있는 자체 포함 HTML 문서로 기록한다.

## 산출물

- 기본 형식은 외부 리소스 없이 열리는 반응형 HTML이다.
- 파일은 `docs/project/APP_INSTALL_METRICS_YYYY_MM_DD_BASELINE.html`에 둔다. 같은 날의 기존 기록을 갱신하는 경우 사용자의 의도와 기존 파일을 먼저 확인한다.
- Markdown은 사용자가 요청했거나 원시 데이터·조사 메모를 별도로 보존할 필요가 있을 때만 추가한다.
- 한 화면에서 핵심 수치를 비교할 수 있는 요약 카드와 플랫폼별 상세 표를 제공하고, 작은 화면과 밝은·어두운 색상 환경에서도 읽을 수 있게 한다.

## 기록 원칙

1. 문서 작성일과 각 콘솔에서 확인 가능한 최신 데이터 기준일을 구분한다.
2. 모든 수치에 지표명, 값, 집계 기간, 플랫폼과 정의를 붙인다. 콘솔 화면에 표시된 명칭을 임의로 다른 개념으로 바꾸지 않는다.
3. iOS의 최초 다운로드 수·전체 다운로드 수·재다운로드 수·옵트인 사용량과 Android의 신규 사용자 확보·설치 사용자·활성 기기는 서로 다른 지표임을 명시한다.
4. 범위와 정의가 다른 수치를 합산해 고유 설치 사용자 수로 표현하지 않는다. 참고용 단순 합계를 보여줄 때는 중복 제거되지 않은 합계라고 눈에 띄게 표시한다.
5. 정확히 관측하지 못한 값은 추정하지 않고 `확인 불가` 또는 데이터 제한으로 기록한다.

## 절차

1. 기존 기준선 문서와 사용자가 지정한 날짜·기간을 확인한다.
2. App Store Connect와 Google Play Console에서 필요한 지표를 직접 확인한다. 로그인이나 권한이 막히면 확인 가능한 범위까지만 기록하고 제한을 밝힌다.
3. 각 지표의 숫자뿐 아니라 화면의 날짜 범위, 최신 반영일, 필터와 데이터 제공 조건을 함께 수집한다.
4. 이전 기준선이 있으면 정의와 기간이 같은 지표만 증감 비교한다.
5. HTML을 생성한 뒤 브라우저에서 레이아웃, 텍스트, 수치와 링크를 확인한다.

## 제약

- Apple의 사용량 지표가 옵트인 데이터라면 전체 설치 사용자 수로 해석하지 않는다.
- 다운로드 수와 현재 설치 사용자 수를 같은 의미로 표현하지 않는다.
- 콘솔의 개인정보나 계정 식별 정보는 문서에 포함하지 않는다.
- 통계 기록 요청만으로 commit 또는 push하지 않는다.
